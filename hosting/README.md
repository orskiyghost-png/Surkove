# Первоначальная установка Majordomo

Сначала проверьте, что на тарифе включены Apache 2.4 `mod_rewrite`, разрешён `RewriteRule` в `.htaccess`, а для PHP 8.3 доступны расширения cURL и ZipArchive. Из Codespace настройки Apache проверить нельзя. До установки релиза `.htaccess` сохраняет доступ к `deploy.php`; активные версии обслуживаются только через Apache Rewrite.

## Подготовка GitHub-доступа панели

Репозиторий `orskiyghost-png/Surkove` публичный. Однако текущий код панели считает пустой `github_token` отсутствующей настройкой и блокирует проверку релиза, поэтому для неё всё ещё нужен Fine-grained Personal Access Token, ограниченный этим репозиторием, с Contents `Read-only` (Metadata: Read-only предоставляется GitHub автоматически). Не используйте этот PAT в GitHub Actions; FTP credentials настраиваются отдельно в GitHub Secrets.

В Codespace скопируйте `LOCAL_ONLY_DO_NOT_COMMIT/deploy-config.php` в приватную папку Majordomo и внесите PAT в поле `github_token`. После подтверждения поддержки Apache у Majordomo установите `apache_rewrite_confirmed` в `true`; до этого панель заблокирует установку и откат. В файле хранится только хеш пароля панели. Не загружайте этот файл в `www` и не добавляйте его в Git.

## Загрузка через файловый менеджер

Загрузите ровно три файла:

| Файл в Codespace | Путь на Majordomo |
| --- | --- |
| `hosting/deploy.php` | `www/deploy.php` |
| `hosting/.htaccess` | `www/.htaccess` |
| `LOCAL_ONLY_DO_NOT_COMMIT/deploy-config.php` | `private/deploy-config.php` (соседняя с `www` папка, вне webroot) |

Рекомендуемые права: каталог `private` — `700`; `private/deploy-config.php` — `600`; `www/deploy.php` и `www/.htaccess` — `644`. Панель не проверяет эти режимы и не хранит служебные данные в `private`: там нужен только конфиг вне публичного `www`. PHP должен уметь записывать в системный временный каталог, а также создавать релизы в `www/releases` и атомарно заменять `www/.htaccess`; это нужно для авторизации, загрузки и переключения сайта. Если хостинг запрещает эти операции, обратитесь в Majordomo за доступом для PHP.

## Установка и управление

1. Дождитесь успешного GitHub Actions workflow и появления ветки `deploy`.
2. Откройте `https://surkove.ru/deploy.php`, войдите паролем панели и проверьте статус GitHub, commit SHA и доступность ZIP.
3. Нажмите «Установить / обновить» только когда будете готовы активировать сборку.
4. Для возврата выберите сохранённый SHA и нажмите «Откатить». Панель хранит максимум пять релизов.

Для временной диагностики можно загрузить `hosting/check-deploy.php` как `www/check-deploy.php`, открыть `https://surkove.ru/check-deploy.php`, ввести пароль панели и проверить статусы PHP, GitHub, ZIP, private, файлов сборки и Apache Rewrite. Скрипт не устанавливает версии; после проверки удалите `www/check-deploy.php`.

Каждый push в `main` собирает сайт и обновляет содержимое ветки `deploy` обычным новым коммитом (без переписывания истории); он не меняет файлы на Majordomo. Production-версия через панель меняется только после нажатия кнопки в панели. `/deploy.php` и `/.well-known/` исключены из правил переключения.

Если `mod_rewrite` или `AllowOverride` недоступны на аккаунте, не запускайте установку: переключение релизов этим способом не сработает. Попросите Majordomo включить RewriteRule или, если тариф это позволяет, настроить DocumentRoot на выбранный каталог релиза; без управления VirtualHost это может быть недоступно. Codespace не имеет доступа к настройкам аккаунта и не может проверить это удалённо.


## Отдельная публикация через FTPS из GitHub Actions

В репозитории добавлен workflow `Majordomo FTPS deployment`. Он запускается **только вручную** из ветки `main` и отправляет только готовую статическую сборку из `dist/`. Он не удаляет удалённые файлы и не передаёт FTP-учётные данные в CI Pull Request.

В настройках репозитория откройте **Settings → Secrets and variables → Actions** и добавьте repository secrets `FTP_USERNAME`, `FTP_PASSWORD`, а также repository variables `FTP_HOST`, `FTP_REMOTE_DIR` и, при необходимости, `FTP_PORT` (если переменную `FTP_PORT` не задать, используется порт `21`). Укажите настоящий FTPS-хост и каталог сайта в том виде, как он виден после входа по FTP; значения-заглушки не используйте. Пароль хранится только в GitHub Secrets.

На вкладке **Actions** откройте **Majordomo FTPS deployment → Run workflow**, выберите `main` и сначала запустите `connection-test`. Затем запустите `smoke-test`: он создаёт уникальный временный файл, скачивает его для сравнения и удаляет; при неподтверждённой очистке job укажет точный путь для проверки. `dry-run` показывает план передачи без изменений на сервере. Только после успешных проверок выбирайте `deploy`.

Публикация выполняется через explicit FTPS (`FTP AUTH TLS`) с проверкой сертификата сервера, TLS для командного и информационного соединений и passive mode. Отключение проверки сертификата и переход на обычный FTP не предусмотрены. В режиме публикации передача останавливается, если удалённый `.htaccess` содержит активный маркер релизов `SURKOVE_ACTIVE_RELEASE`: существующая PHP-панель направляет трафик в `www/releases/<SHA>`, поэтому прямая загрузка в корень сайта не активировала бы новую версию. В таком состоянии используйте существующую панель для установки/отката; не меняйте `FTP_REMOTE_DIR` на каталог `releases` в попытке обойти защиту.

FTPS-режим не зеркалит с удалением: старые assets и другие удалённые файлы остаются на сервере. Передача обновляет файлы сборки по одному и не является атомарным переключением релиза; при сбое сайт может временно содержать смесь файлов. Этот путь не заменяет панель релизов и не делает rollback на сервере: для отката кода создайте Revert Pull Request в `main`, после merge повторите ручной `deploy` (при активном маркере панели используйте её штатный rollback). Миграции БД не выполняются.

## Проверки и ограничения Majordomo

Сборка и репозиторий не позволяют проверить параметры конкретного аккаунта Majordomo. До реальной публикации владелец должен подтвердить в панели хостинга FTP-хост/порт, каталог FTP, возможность explicit FTPS и соответствие каталога фактическому `DocumentRoot`. Smoke-test проверяет права чтения/записи/удаления только в заданном каталоге, а не корректность настройки домена или работу Apache.

Существующая PHP-панель отдельно зависит от PHP 8.3, расширений cURL и ZipArchive, а также Apache 2.4 `mod_rewrite` и разрешения `RewriteRule` через `.htaccess`; эти функции должны быть подтверждены у Majordomo. FTPS workflow не проверяет доступность SSH/SFTP и не использует эти протоколы. Не запускайте первую публикацию, пока не подтверждены каталог назначения и выбранный способ активации версии.
