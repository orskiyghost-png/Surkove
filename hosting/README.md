# Первоначальная установка Majordomo

Сначала проверьте, что на тарифе включены Apache 2.4 `mod_rewrite`, разрешён `RewriteRule` в `.htaccess`, а для PHP 8.3 доступны расширения cURL и ZipArchive. Из Codespace настройки Apache проверить нельзя. До установки релиза `.htaccess` сохраняет доступ к `deploy.php`; активные версии обслуживаются только через Apache Rewrite.

## Подготовка приватного GitHub-доступа

Репозиторий `orskiyghost-png/Surkove` приватный, поэтому панели нужен Fine-grained Personal Access Token. Создайте токен только для этого репозитория и оставьте для Contents разрешение `Read-only` (Metadata: Read-only предоставляется GitHub автоматически). Не используйте PAT в GitHub Actions.

В Codespace скопируйте `LOCAL_ONLY_DO_NOT_COMMIT/deploy-config.php` в приватную папку Majordomo и внесите PAT в поле `github_token`. После подтверждения поддержки Apache у Majordomo установите `apache_rewrite_confirmed` в `true`; до этого панель заблокирует установку и откат. В файле хранится только хеш пароля панели. Не загружайте этот файл в `www` и не добавляйте его в Git.

## Загрузка через файловый менеджер

Загрузите ровно три файла:

| Файл в Codespace | Путь на Majordomo |
| --- | --- |
| `hosting/deploy.php` | `www/deploy.php` |
| `hosting/.htaccess` | `www/.htaccess` |
| `LOCAL_ONLY_DO_NOT_COMMIT/deploy-config.php` | `private/deploy-config.php` (соседняя с `www` папка, вне webroot) |

Рекомендуемые права: каталог `private` — `700`; `private/deploy-config.php` — `600`; `www/deploy.php` и `www/.htaccess` — `644`. Панель не блокирует работу, если файловый менеджер не позволяет выставить эти режимы: важно, чтобы `private` находился вне `www` и PHP мог создавать в нём служебные файлы (лимит входов, блокировку операций и состояние). Конфигурация содержит доступ к приватному GitHub-репозиторию и не должна находиться в `www`. Если PHP не может записывать в `private`, установка и авторизация покажут отдельную ошибку доступа.

## Установка и управление

1. Дождитесь успешного GitHub Actions workflow и появления ветки `deploy`.
2. Откройте `https://surkove.ru/deploy.php`, войдите паролем панели и проверьте статус GitHub, commit SHA и доступность ZIP.
3. Нажмите «Установить / обновить» только когда будете готовы активировать сборку.
4. Для возврата выберите сохранённый SHA и нажмите «Откатить». Панель хранит максимум пять релизов.

Для временной диагностики можно загрузить `hosting/check-deploy.php` как `www/check-deploy.php`, открыть `https://surkove.ru/check-deploy.php`, ввести пароль панели и проверить статусы PHP, GitHub, ZIP, private, файлов сборки и Apache Rewrite. Скрипт не устанавливает версии; после проверки удалите `www/check-deploy.php`.

Каждый push в `main` собирает сайт и полностью заменяет содержимое ветки `deploy`; он не меняет файлы на Majordomo. Production-версия меняется только после нажатия кнопки в панели. `/deploy.php` и `/.well-known/` исключены из правил переключения.

Если `mod_rewrite` или `AllowOverride` недоступны на аккаунте, не запускайте установку: переключение релизов этим способом не сработает. Попросите Majordomo включить RewriteRule или, если тариф это позволяет, настроить DocumentRoot на выбранный каталог релиза; без управления VirtualHost это может быть недоступно. Codespace не имеет доступа к настройкам аккаунта и не может проверить это удалённо.
